# 延遲校正與手動微調設計

## 問題

目前自動校正以點擊順序 `0, 1, 2, 3` 推算預期節拍，因此玩家若在節拍器開始數秒後才開始點擊，等待的完整拍數會被誤算成輸入延遲。已觀察到儲存值 `4.906077` 秒，導致 Tap 與 Flick 的事件時間被移出判定區間，而持續接觸型 Checkpoint 仍可正常判定。

## 自動校正

- 每次 TAP 以校正開始後的經過時間，對齊時間上最近的 0.6 秒節拍。
- 每筆樣本只保留該節拍的相位誤差，範圍為 -300 ms 至 +300 ms，不再包含等待的完整拍數。
- 四筆相位誤差取平均後儲存並立即套用。
- 啟動時讀取舊值；非有限值或絕對值大於 300 ms 時視為無效，重設並儲存為 0 ms。

## 手動調整

- 延遲校正面板持續顯示目前套用值，單位為毫秒。
- 提供 `−10 ms`、`＋10 ms` 與 `歸零` 三個按鈕。
- 每次調整後立即更新執行中數值、畫面文字與 PlayerPrefs。
- 手動值限制在 -300 ms 至 +300 ms，避免再次產生足以讓所有離散音符失效的偏移。

## 介面配置

- 保留現有自動校正 TAP 流程。
- 校正面板加高，將目前值與三個手動按鈕放在 TAP 操作下方，返回按鈕保留在底部。
- 自動校正完成後，畫面顯示新的平均值；玩家可接著用 10 ms 步進微調。

## 驗證

- `4.906077` 秒的校正點擊應解析為最接近節拍的 `0.106077` 秒相位誤差。
- 儲存的 `4.906077` 秒舊值應在啟動時回復為 `0`。
- `±10 ms` 與歸零操作應更新目前值並保持在 `±300 ms` 範圍內。
- 執行既有 RuntimeValidation，確認 Tap、Flick、Checkpoint 與判定保護回歸測試全部通過。
